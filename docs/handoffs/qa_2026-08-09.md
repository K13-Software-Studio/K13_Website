## What was tested

**Pages:** `index.html` (main site) and `pricing/tiger/index.html` (Tiger Hospitality pricing playbook,
the only file under `pricing/`).

**Viewports:** 1440×900 (desktop), 390×844 (iPhone-class mobile), plus three CSS-breakpoint boundary
checks the site itself defines: 880×1024 (near the 880px hero-grid breakpoint), 600×900 (the 600px nav
breakpoint), and 320×700 (smallest common device width).

**Checks performed, for real, in the browser:**
- Full page load, console errors, uncaught page errors, failed network requests, HTTP ≥400 responses —
  at all five viewports, on both pages. **Zero found anywhere.**
- Horizontal overflow (`scrollWidth` vs `clientWidth`) — checked at all five viewports on both pages.
  **No overflow at any width, including 320px.**
- Every nav anchor link (`#approach`, `#work`, `#about`, `#contact`) — clicked, confirmed smooth-scroll
  lands within ~30-45px of the target (fixed-header offset), no dead links.
- The 4-step "What are we building?" contact wizard — clicked through step 1→2 on desktop and via `.tap()`
  on a real mobile/touch-emulated context; back button appears correctly, state advances correctly.
- The hover "peek" image preview on desktop work rows — hovered, confirmed it swaps in the correct
  `assets/shots/*.jpg` for the row and the image actually loads (checked `img.src` + no 404).
- The touch/no-hover fallback (`.rthumb` inline screenshot shown instead of the hover peek below 920px
  or on touch devices) — confirmed it renders inline and loads the correct image on a real mobile context.
- All 10 external portfolio links (Tiger, La Vida, Miramar, CENGO, Station8, Global Fork, Egg&Out,
  TrustMeBro, baa atelier, BarFix) — verified `target="_blank" rel="noopener"` on every one.
- `mailto:`/`tel:` links in the contact section and footer — verified correct hrefs.
- Scroll-reveal animation (`.rv` class, IntersectionObserver-driven) — verified with a real incremental
  scroll-through (not a jump) that all 24 reveal elements on the page actually receive the `.in` class
  and become visible; 0 stuck at opacity 0.
- `prefers-reduced-motion: reduce` — emulated via Playwright's `emulate_media`. Confirmed the site's own
  CSS override (`@media(prefers-reduced-motion:reduce)`) correctly forces every `.rv` element to
  `opacity:1` immediately with no animation, and produces zero console errors. **Honoured correctly.**
- The Tiger pricing calculator (`pricing/tiger/`) — clicked the `+`/`-` quantity steppers, confirmed the
  live summary drawer auto-opens on quantity change (`render(); open();` in the page's own script) and
  computes correctly: 3× Concept Site → `$3,600` site total, Founding Partner discount applied, 40%
  deposit / 60%-before-launch split computed correctly (`$1,440` / `$2,160`). The "TEKLİF" tab correctly
  toggles the drawer open/closed. **This works correctly** — my first pass at testing it produced a false
  positive (looked closed in a screenshot) that turned out to be my own test script using a scrolled
  viewport and a `force:true` click; re-tested cleanly three ways (plain click, `elementFromPoint` +
  `mouse.click`, and a direct classList check before/after) and the toggle and auto-open both behave
  correctly every time. Flagging this here so it isn't mistaken for a fixed bug in a future pass — it was
  never broken.

## Findings

**No functional defects found.** Everything exercised above worked exactly as designed, on both pages,
at every viewport tested, with zero console errors and zero failed/4xx+ requests.

**One UX observation (not a bug, worth a design call):** below the 600px breakpoint, `nav .nl{display:none}`
hides the Approach/Work/Studio nav links entirely, and there is no hamburger menu or any other mobile-nav
affordance in the markup (`grep` for hamburger/menu-toggle patterns returns nothing). Below 600px wide,
the only way to reach those sections is to scroll manually — the "Start a project" CTA remains reachable.
This is defensible for a short single-page site (a visitor lands, reads top to bottom, hits the CTA) but
it's a deliberate trade-off, not an oversight to "fix" reflexively — flagging for Kazim's call, not
treating as a defect.
