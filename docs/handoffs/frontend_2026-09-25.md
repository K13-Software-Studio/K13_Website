## Summary
Built the approved v6 "sculpt" loading-screen prototype
(`docs/prototypes/sculpt/v6.html`, Kazim-approved 2026-09-25 after six rounds) into the real
site, faithfully. First visit: a full-screen opening overlay plays a short self-hosted film of
the K13 mark being sculpted, over a skeleton version of the real hero, then hands over to the
real page. No other section, copy, or colour was touched.

**What it does**
- Light paper ground, real hero reproduced as soft grey skeleton blocks with a slow shimmer —
  built by reusing the site's own `.hero` / `.hero-grid` / `.wrap` / `.status-wrap` classes, so
  it collapses to one column at the same 920px break the real hero uses, for free, with no
  duplicated breakpoint logic.
- Orange lens + beam above a 16:9 frame that opens from a line of light only once the video's
  `playing` event fires. Poster is the first frame (`k13-statue-first.jpg`), never the last.
- Video plays at `playbackRate 1.2`, muted, `playsinline`; `play()` is called at ~120ms, no
  warm-up.
- A fluid changing line under the frame (Fraunces italic, ink with an orange sheen sweep) follows
  the video's `currentTime` through the six approved captions; "Loading the studio" breathes
  below it in JetBrains Mono.
- On `ended`, +450ms, the skeleton resolves into the real page and the frame lifts off; the
  overlay node is fully removed from the DOM 1.5s later.

**Rails, all present**
- Plays once per visit via `sessionStorage['k13-projected']` (the prototype had this disabled
  for review; the real site enables it).
- `?intro` on the URL forces a replay for review, ignoring the once-per-visit flag for that load
  only (it still writes the flag on handover, so a plain reload afterward stays quiet).
- "Skip intro" button (48px tall, well over the 44px floor), focused on load, visible focus
  ring; `Esc` does the same. Both hand over immediately.
- `prefers-reduced-motion: reduce` → the overlay never renders at all (`display:none` folded
  into the site's existing reduced-motion media query, plus a JS bail that never touches
  `sessionStorage` or the video).
- `play()` rejection or a video `error` → hand over immediately.
- ~14s hard ceiling regardless of video state.
- Body scroll locked (`html`/`body` `overflow:hidden`) only while the overlay is up.

**Accessibility**
- The real page sits behind the overlay with `inert` (not just `opacity:0`) on every one of its
  top-level siblings while held — so it is genuinely out of the tab order and off for assistive
  tech, not just invisible. This project's own `CLAUDE.md` already carries the scar from that
  exact mistake once (`opacity:0; pointer-events:none` on the contact stepper leaving hidden
  steps focusable); I did not repeat it here.
- Video is `aria-label`led; veil, bones, beam, lens, and the dust canvas are `aria-hidden`; the
  changing line + "Loading the studio" sit in one `aria-live="polite"` region, exactly like the
  approved prototype.
- axe-core: **zero violations**, desktop (1440) and mobile (390), both mid-overlay and after
  handover. (One caveat below.)

**Lenis**
- `startLenis()` now also does `window.__k13Lenis = lenis;` and self-stops if the overlay is
  still up at the moment Lenis initializes (2-line addition, handles either load-order). The
  overlay's handover calls `.start()`. No fighting between the lock and smooth scroll in either
  direction.

**CSP**
- No change to `vercel.json`. Video and poster are self-hosted under `assets/intro/`, covered by
  the existing `default-src 'self'` (no separate `media-src` directive existed to add). Proved
  by serving the exact `vercel.json` headers locally (minus HSTS, per your instruction) and
  running the full Playwright pass against that server: **zero console CSP violations**,
  confirmed twice — once via the general console-error check, once via a dedicated
  "Content Security Policy" / "Refused to" string grep across both viewport runs.

## Risks / caveats
- **axe timing note, not a defect:** a scan taken at the literal instant the overlay's `.on`
  class is added catches the Skip button mid-way through its own approved fade-in
  (`opacity:0` → `1` over a `.6s`-delayed `.6s` transition, ported verbatim from the prototype)
  and reports a transient contrast dip. That is axe correctly reading an opacity-blended color
  during an animation frame, not a static contrast failure — it clears on its own within ~1.2s,
  and every scan taken at a settled moment (mid-overlay after the fade completes, or after
  handover) is clean. I did not shorten or otherwise alter this fade timing: it is exactly what
  Kazim approved across six prototype rounds, and the brief dip is inherent to any element that
  fades in from transparent. Flagging it here rather than silently changing approved motion.
- **Dust canvas is drawn but invisible**, exactly as in the approved v6 prototype: its CSS sets
  `opacity:0` in both the "on" and "up" states (I checked — this isn't a porting slip, the
  prototype's own CSS does the same). I preserved this exactly rather than "fixing" it to
  opacity 1, since that would be a visual change beyond what was approved. If Kazim actually
  wants the dust motes visible, that's a one-line CSS change (`#k13intro.on .k13intro-dust` →
  `opacity:1`) — flagging it rather than deciding it myself.
- **Bones-hide trigger simplified vs. the prototype's literal CSS**: the prototype hides the
  skeleton via two overlapping selectors (`body:not(.held) .bones` and `.proj.up .bones`), both
  firing at the same moment since the JS toggles both classes together. I implemented this with
  a single equivalent selector (`#k13intro.up .k13intro-bones{opacity:0}`) rather than porting
  the redundant second selector. Net visible behavior is identical; noting the simplification
  for transparency.
- `assets/intro/` adds ~1.15MB to the repo (video + poster), fetched only on a first visit that
  isn't reduced-motion — never fetched otherwise (see CSP/rails above).
- The dev server (`http.server 9130` on the old checkout) was killed and replaced with a
  header-matching server on the cabin, left running per instructions. It intentionally omits
  `Strict-Transport-Security` for the local HTTP proof; every other `vercel.json` header is
  present verbatim.
- `pricing/tiger/` and branch-protection-on-main are pre-existing open decisions, untouched here.
